# 🏗️ معماری پروژه (Architecture) — Hokm Pro

این سند توضیح می‌دهد که اجزای مختلف بازی «حکم حرفه‌ای» چگونه در کنار هم کار می‌کنند. معماری این پروژه بر پایه‌ی **جداسازی مسئولیت‌ها (Separation of Concerns)** بنا شده است؛ یعنی منطق بازی (Game Logic) کاملاً از رابط کاربری (UI) و مدیریت داده‌ها جدا است.

---

## 📁 نمای کلی ساختار پروژه

```text
hokm-pro/
├── index.html              # نقطه ورود برنامه (Single Page Application)
├── 404.html                # صفحه خطای سفارشی
├── server.py               # سرور Flask برای فایل‌های استاتیک و Socket.io
├── requirements.txt        # وابستگی‌های پایتون

│   ├── themes.css          # ۵ تم رنگی، ۵ تم کارت و ۵ تم پس‌زمینه
│   ├── components.css      # استایل‌های عمومی (دکمه‌ها، کارت‌ها، مودال‌ها)
│   ├── screens.css         # استایل اختصاصی هر صفحه (منو، بازی، پروفایل)
│   ├── animations.css      # ۴۵+ انیمیشن (پرتاب کارت، برنده شدن، ...)

└── js/                     # منطق و عملکرد برنامه
    ├── storage.js          # مدیریت localStorage و migration داده‌ها
    ├── themes.js           # مدیریت تم‌ها (شب/روز، رنگی)
    ├── audio.js            # موتور صدا با Web Audio API (بدون فایل خارجی)
    ├── profile.js          # پروفایل، ELO، سکه و جایزه روزانه

    ├── friends.js          # سیستم دوستان
    ├── tournament.js       # مدیریت تورنمنت‌ها
    ├── replay.js           # ذخیره و پخش مجدد بازی‌ها
    ├── share.js            # ساخت تصویر نتیجه با Canvas و اشتراک‌گذاری

    ├── ui.js               # مدیریت رابط کاربری و رندر کارت‌ها
```

لایه‌های معماری (Architecture Layers)

پروژه از سه لایه اصلی تشکیل شده است:

۱. لایه داده (Data Layer)

· فایل‌ها: storage.js
· وظیفه: ذخیره و بازیابی اطلاعات در حافظه مرورگر (LocalStorage). این لایه تضمین می‌کند که اگر کاربر مرورگر را ببندد، پیشرفت او (سکه، آمار، تم‌ها) حفظ شود.

۲. لایه منطق (Logic Layer)

· فایل‌ها: game.js, ai.js, profile.js, achievements.js
· وظیفه: این لایه هیچ کاری با HTML و DOM ندارد. فقط قوانین بازی، محاسبات ریاضی (مثل ELO)، و رفتار هوش مصنوعی را مدیریت می‌کند. این جداسازی باعث می‌شود اگر بخواهی بعداً بازی را به یک اپلیکیشن موبایل نیتیو تبدیل کنی، بتوانی از همین منطق استفاده کنی.

۳. لایه نمایش (Presentation Layer)

· فایل‌ها: ui.js, screens.css, components.css
· وظیفه: نمایش کارت‌ها روی صفحه، مدیریت کلیک‌ها، انیمیشن‌ها و تغییر صفحات.

---

🔄 چرخه حیات بازی (Game Flow)

1. کاربر وارد index.html می‌شود.
2. main.js تمام ماژول‌های JS را بررسی و راه‌اندازی می‌کند.
3. کاربر روی «شروع بازی» کلیک می‌کند.
4. ui.js به game.js سیگنال می‌دهد که بازی جدید شروع شود.
5. game.js کارت‌ها را توزیع کرده و نوبت‌ها را مدیریت می‌کند.
6. اگر نوبت بازیکن انسانی باشد، ui.js کارت‌ها را قابل کلیک می‌کند.
7. اگر نوبت هوش مصنوعی باشد، game.js از ai.js می‌خواهد که بهترین حرکت را انتخاب کند.
8. در پایان بازی، profile.js سکه و ELO را محاسبه کرده و در storage.js ذخیره می‌کند.

---

🌐 بخش آنلاین (Server Architecture)

· فایل server.py: این فایل هم وظیفه سرو کردن فایل‌های استاتیک (HTML/CSS/JS) را دارد و هم یک سرور WebSocket با استفاده از Flask-SocketIO است.
· ارتباط بلادرنگ: برای اینکه کارت‌ها در بازی آنلاین با تأخیر نمایش داده نشوند، از Socket.io استفاده شده است. هر بازیکن به یک «اتاق» (Room) با کد ۶ رقمی متصل می‌شود.
· پایگاه داده: یک فایل hokm.db (SQLite) برای ذخیره اطلاعات کاربران (در صورت پیاده‌سازی لاگین) و تاریخچه بازی‌ها استفاده می‌شود.
